System and services

How info.destaben.dev is put together: a static site published on GitHub Pages and, separately, a self-hosted relay (lab.destaben.dev) from which the browser gets live data. It complements the code architecture.

Meshtastic in detail

A Meshtastic gateway node (LoRa radio) is connected to Home Assistant through its Meshtastic integration. The relay never speaks to the radio: it reads fixed entities (gateway state, node name, uptime, battery, node counts, traffic and error rates, public-channel messages) and fires one fixed event.

Three different views come from the same source: the gateway panel (/v1/lab/meshtastic), the mesh status (/v1/lab/meshtastic-status) and the send form (POST /v1/lab/meshtastic/messages).

LoRaMediumFastTurnstile

What Meshtastic never exposes

No entity IDs, full node identifiers (the last two characters are masked), positions, SNR/RSSI, routes, channel keys, direct messages, unbounded history or controls. Channels publish only when allowlisted and at most 16; direct-message channels must be denylisted.

Meshtastic send path

  1. Turnstile token + one printable line ≤ 237 bytes.
  2. The relay validates with siteverify and applies per-client and global cooldowns.
  3. Fires meshtastic_public_broadcast in Home Assistant.
  4. An automation maps it only to script.meshtastic_public_broadcast, which transmits over the radio.

202 means Home Assistant accepted the event, not that the mesh delivered it.

4. Main flows

Publishing a change

  1. A PR to main is opened: ci.yml runs pytest, Compose config and npm run verify.
  2. On merge, deploy-pages.yml repeats the checks, builds (querying the GitHub API) and uploads dist/.
  3. GitHub Pages serves the new site at info.destaben.dev.
static

Updating the relay

  1. A push to main touching services/signal-relay/** publishes ghcr.io/destaben/signal-relay (amd64 and arm64).
  2. On the host, preflight.sh and deploy.sh recreate only the signal-relay container.
  3. verify.sh checks health and contracts; rollback.sh reverts.
service

A panel requests data

  1. The browser sends GET lab.destaben.dev/v1/lab/… with a timeout.
  2. Cloudflare → cloudflared → nginx, which lets only listed routes and methods through and rate-limits (120/min per IP).
  3. The relay answers from cache or asks the origin (Home Assistant, Prometheus, Moonraker…).
  4. It returns only the public projection; on any failure, an “unavailable” state.
dynamic

Incoming Reticulum message

  1. An LXMF client writes to the public address.
  2. The bridge stores the text in the inbox (≤ 1,000 characters) and updates metrics.
  3. Afterwards, without blocking delivery, it notifies Telegram if credentials exist.
  4. The site sees it in /v1/inbox as anonymous plain text.
Reticulum

Visitor sends to Meshtastic

  1. The Turnstile widget hands a token to the browser.
  2. POST with message + turnstileToken.
  3. The relay validates with siteverify, applies cooldowns and fires the event in Home Assistant.
  4. An automation maps it only to script.meshtastic_public_broadcast.
anti-abuse

Printer panel

  1. Polls every 15 s (backoff up to 120 s).
  2. The relay queries Moonraker and, during a print, downloads and parses the G-code in the background.
  3. The browser receives a modelId (HMAC), downloads the light model and draws the layers already printed.
  4. With no active job, it shows a fallback animation.

6. Security and privacy limits

Nothing sensitive in the repository

The Reticulum identity, Telegram and Home Assistant tokens, the Turnstile secret, tunnel configuration and .env live only on the host.

Fixed projections

The relay does not forward upstream responses: it builds objects from allowed fields. It publishes no entities, attributes, filenames, IPs, routes or topology.

Default-deny

Meshtastic channels behind an allowlist, printer and educational sending disabled, nginx with an allowlist of routes and methods.

Bounded origin

CORS and the WebSocket accept https://info.destaben.dev. Upstreams are reached without following redirects, with maximum size and time.

Hardened container

Read-only filesystem, cap_drop: ALL, no-new-privileges, no published port and a single external network.

Anti-abuse

Turnstile on the only POST with a physical effect (radio), per-client and global cooldowns and 120 req/min per IP at the edge.
