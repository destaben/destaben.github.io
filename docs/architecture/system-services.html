Sistema y servicios

Cómo se compone info.destaben.dev: un sitio estático que se publica en GitHub Pages y, aparte, un relay autohospedado (lab.destaben.dev) del que el navegador obtiene los datos en vivo. Complementa la arquitectura del código.

1. Mapa de componentes

Dos caminos independientes: el contenido estático llega desde GitHub Pages; los datos dinámicos llegan por el edge privado. Si el relay cae, la web sigue cargando y cada panel muestra su estado «no disponible».

3. Flujos principales

Publicar un cambio

  1. Se abre un PR a main: ci.yml corre pytest, Compose config y npm run verify.
  2. Al fusionar, deploy-pages.yml repite las pruebas, compila (consultando la API de GitHub) y sube dist/.
  3. GitHub Pages sirve el nuevo sitio en info.destaben.dev.
estático

Actualizar el relay

  1. Un push a main que toque services/signal-relay/** publica ghcr.io/destaben/signal-relay (amd64 y arm64).
  2. En el host, preflight.sh y deploy.sh recrean solo el contenedor signal-relay.
  3. verify.sh comprueba salud y contratos; rollback.sh revierte.
servicio

Un panel pide datos

  1. El navegador hace GET lab.destaben.dev/v1/lab/… con un timeout.
  2. Cloudflare → cloudflared → nginx, que solo deja pasar rutas y métodos listados y limita la tasa (120/min por IP).
  3. El relay responde desde caché o pide al origen (Home Assistant, Prometheus, Moonraker…).
  4. Devuelve solo la proyección pública; ante cualquier fallo, estado «no disponible».
dinámico

Mensaje entrante por Reticulum

  1. Un cliente LXMF escribe a la dirección pública.
  2. El puente guarda el texto en la bandeja (≤ 1000 caracteres) y actualiza métricas.
  3. Después, y sin bloquear la entrega, avisa por Telegram si hay credenciales.
  4. La web lo ve en /v1/inbox como texto plano anónimo.
Reticulum

Visitante envía a Meshtastic

  1. El widget Turnstile entrega un token al navegador.
  2. POST con message + turnstileToken.
  3. El relay valida con siteverify, aplica cooldowns y lanza el evento en Home Assistant.
  4. Una automatización lo mapea solo a script.meshtastic_public_broadcast.
anti-abuso

Panel de la impresora

  1. Sondeo cada 15 s (backoff hasta 120 s).
  2. El relay consulta Moonraker y, durante una impresión, descarga y analiza el G-code en segundo plano.
  3. El navegador recibe un modelId (HMAC), descarga el modelo ligero y dibuja las capas ya impresas.
  4. Sin trabajo activo, muestra una animación de reserva.

5. Límites de seguridad y privacidad

Nada sensible en el repositorio

Identidad Reticulum, tokens de Telegram y Home Assistant, secreto de Turnstile, configuración del túnel y .env viven solo en el host.

Proyecciones fijas

El relay no reenvía respuestas de origen: construye objetos con campos permitidos. No publica entidades, atributos, nombres de archivo, IPs, rutas ni topología.

Default-deny

Canales de Meshtastic con allowlist, impresora y envío educativo desactivados, nginx con lista blanca de rutas y métodos.

Origen acotado

CORS y WebSocket aceptan https://info.destaben.dev. Los upstreams se alcanzan sin seguir redirecciones, con tamaño y tiempo máximos.

Contenedor endurecido

Sistema de archivos de solo lectura, cap_drop: ALL, no-new-privileges, sin puerto publicado y una sola red externa.

Anti-abuso

Turnstile en el único POST con efecto físico (radio), cooldowns por cliente y global y 120 req/min por IP en el edge.
