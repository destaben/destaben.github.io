# David Estabén's Website

Source for [info.destaben.dev](https://info.destaben.dev), a bilingual static Astro portfolio deployed to GitHub Pages from `main`.

## Requirements

- Node.js 22.23.4 or newer (`engines` in `package.json`; `.nvmrc` pins the 22 line).
- npm 10 or newer.

## Project Structure

- `src/pages/` contains routes; `/`, `/es/`, and `/en/` render the portfolio.
- `src/components/`, `src/layouts/`, and `src/styles/` provide shared markup and presentation.
- `src/components/react/` contains the React islands (section labels, animated headings and copy, magnetic buttons, click sparks, scroll reveals, and the decorative glitch backdrop); `DecryptedText.tsx`, `BlurText.tsx`, `ShinyText.tsx`, `Magnet.tsx`, `ClickSpark.tsx`, and `LetterGlitch.tsx` are adapted from React Bits and keep their attribution headers (`SectionLabel.tsx`, `Reveal.tsx`, `CopySpark.tsx`, and `GlitchBackdrop.tsx` are original wrappers), and `THIRD_PARTY_NOTICES.md` reproduces the upstream license. They are used on a non-profit personal website and are not redistributed as standalone components (React Bits is MIT + Commons Clause). The glitch backdrop renders nothing without JavaScript, under reduced motion, or on narrow screens; headings, copy, and grids show their final state at once under reduced motion and without JavaScript (a `noscript` rule and a reduced-motion rule override the hidden starting state). The hero orbit and log animations and the card spotlight are plain CSS and a small script.
- `src/data/portfolio.ts` contains localized portfolio content.
- `src/lib/github.ts` fetches every public repository from `destaben` during each build.
- `src/lib/printer-lab.mjs` holds the framework-free rules of the 3D printer laboratory (state mapping, path decoding, projection, backoff). The Node test suite imports it directly, and `printer-lab.d.mts` types it for Astro.
- `src/content/blog/` contains localized Markdown or MDX technical notes published in the portfolio and RSS feed.
- `public/` contains assets served unchanged, including `CNAME`, brand assets, and future downloadable files.
- `docs/DESIGN-GUIDELINES.md` defines public content, branding, accessibility, and live-service rules.
- `docs/SIGNAL-RELAY.md` defines the separate Reticulum bridge contract and self-hosted deployment boundary.
- `dist/` is generated by Astro and must not be committed.

## Local Development

Install the lockfile-defined dependencies:

```sh
npm ci
```

Start the development server:

```sh
npm run dev
```

Check Astro and TypeScript diagnostics:

```sh
npm run check
```

Run the generated-site regression suite:

```sh
npm test
```

Create and inspect a production build:

```sh
npm run build
npm run preview
```

## Content

Update the Spanish and English structured content in `src/data/portfolio.ts` together. Keep technical claims public, specific, and verifiable; do not add corporate or home-network details. The existing GitHub client can support a future project archive, but the landing page prioritizes selected engineering evidence.

Add articles as Markdown or MDX files in `src/content/blog/`, with `title`, `description`, `locale`, and `pubDate` frontmatter; `tags`, `updatedDate`, and `draft` are optional. Published notes appear in the localized portfolio sections and at `/en/notes/<slug>/` or `/es/bitacora/<slug>/`. Draft entries are excluded from those routes and from `/rss.xml`.

## Signal Relay

The portfolio presents a public LXMF destination backed by a separate, self-hosted Reticulum bridge. It provides a contact address and bounded plain-text inbox; Prometheus scrapes operational metrics separately. Its public API, security boundary, container deployment, and acceptance checks are defined in [docs/SIGNAL-RELAY.md](docs/SIGNAL-RELAY.md) and [services/signal-relay/README.md](services/signal-relay/README.md). Do not add Reticulum identities, Telegram credentials, tunnel credentials, home IP addresses, or bridge configuration to this repository.

For local bridge setup, API/WebSocket tests, and end-to-end verification, use [services/signal-relay/README.md](services/signal-relay/README.md). GitHub Actions runs both the Astro suite and Signal Relay's Python suite before publishing the Pages artifact, and runs them again on pull requests through `ci.yml` (see Deployment).

When refreshing Reticulum bootstrap transports or recovering a broken private configuration, follow the relay README's host procedure: preserve `.env`, the persistent relay data volume, and `lab-sender-reticulum/`; refresh the relay `compose.yaml` and merge the current Reticulum template, then recreate only `signal-relay`. Update the edge independently from [`destaben/lab-inverse-proxy`](https://github.com/destaben/lab-inverse-proxy). Update the private `SIGNAL_RELAY_PUBLIC_TCP_NODE_ALIASES` mapping whenever configured interface names change, and keep its public aliases aligned with `SIGNAL_RELAY_PUBLIC_TCP_NODE_URLS`.

## Deployment

Every push to `main`, and every manual `workflow_dispatch`, runs [.github/workflows/deploy-pages.yml](.github/workflows/deploy-pages.yml). The workflow uses Node 22.23.4 (the minimum Astro and `@astrojs/react` require), runs `npm ci`, runs the Signal Relay `pytest` suite and `npm run verify` (Astro check, tests and build), and deploys the generated `dist/` artifact to GitHub Pages. GitHub Actions is the only publishing path; do not commit generated files or publish from a branch.

Every pull request to `main`, and every manual `workflow_dispatch`, runs [.github/workflows/ci.yml](.github/workflows/ci.yml) with read-only permissions: the Signal Relay `pytest` suite, `docker compose config` validation, and `npm run verify` (Astro check, tests and build). Its actions are pinned to commit SHAs. It deploys nothing, passes only the default read-only `GITHUB_TOKEN` to the build, and references no repository secrets (a collaborator with write access can still change the workflow in their own branch, so keep secrets out of reach with environment protection); make its jobs required status checks in branch protection if you want merges gated on them. The check names are `Signal Relay tests` and `Site check, tests and build`; use exactly those names. Each job has a 15-minute timeout. The site job passes `PUBLIC_TURNSTILE_SITE_KEY` from the repository variable `TURNSTILE_SITE_KEY` only; if the key is stored as a secret instead, PR builds omit it and differ slightly from the Pages build.

In repository settings, set Pages **Source** to **GitHub Actions**. The published artifact includes `public/CNAME`; this preserves the domain in deployed files but does not configure the custom domain in GitHub by itself.

## Meshtastic Status Rollout

The Meshtastic status panel depends on two other deployments, so roll it out in this order. Until step 2 is live, the panel shows its unavailable state.

1. **Relay image and host.** Merge the relay change to `main`. `.github/workflows/publish-signal-relay.yml` publishes the image from `main`. On the relay host, deploy it with `services/signal-relay/scripts/deploy.sh`, after confirming the private `.env` contains the Meshtastic entity map. Before enabling the channel projection, set `SIGNAL_RELAY_MESHTASTIC_CHANNEL_ALLOWLIST` to the public channels only (empty publishes none) and check every direct-message entity against `docs/MESHTASTIC-INVENTORY.md` step 5b, denylisting any it finds. The relay refuses to start on a malformed entity ID or invalid channel setting, so confirm it is running after recreation. Channel settings are described in [services/signal-relay/README.md](services/signal-relay/README.md).
2. **Edge allowlist.** Add the `GET /v1/lab/meshtastic-status` entry in [`destaben/lab-inverse-proxy`](https://github.com/destaben/lab-inverse-proxy) (PR #7) and deploy the edge. Until this exists, the public route is not reachable through `lab.destaben.dev`.
3. **Site.** Merge the portfolio change to `main`. GitHub Pages publishes the panel from that merge.

## 3D Printer Rollout

The 3D printer panel shows its unavailable state until the relay's printer routes and the edge's `8082` listener and allowlist entries are live. Follow the rollout order in [docs/SIGNAL-RELAY.md](docs/SIGNAL-RELAY.md#3d-printer-laboratory). The site needs no extra step.

## Custom Domain

Set the Pages custom domain to `info.destaben.dev`, then create this DNS record at the authoritative DNS provider:

```text
info.destaben.dev CNAME destaben.github.io
```

Use DNS-only mode for this CNAME. Wait for GitHub to verify DNS and issue its certificate before enforcing HTTPS.
