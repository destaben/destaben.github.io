# David Estabén's Website

Source for [info.destaben.dev](https://info.destaben.dev), a bilingual static Astro portfolio deployed to GitHub Pages from `main`.

## Requirements

- Node.js 22 LTS, as pinned in `.nvmrc`.
- npm 10 or newer.

## Project Structure

- `src/pages/` contains routes; `/`, `/es/`, and `/en/` render the portfolio.
- `src/components/`, `src/layouts/`, and `src/styles/` provide shared markup and presentation.
- `src/data/portfolio.ts` contains localized portfolio content.
- `src/lib/github.ts` fetches every public repository from `destaben` during each build.
- `src/content/blog/` contains localized Markdown or MDX technical notes published in the portfolio and RSS feed.
- `public/` contains assets served unchanged, including `CNAME`, brand assets, and future downloadable files.
- `docs/DESIGN-GUIDELINES.md` defines public content, branding, accessibility, and live-service rules.
- `docs/SIGNAL-RELAY.md` defines the separate Reticulum bridge contract and self-hosted deployment boundary.
- `dist/` is generated by Astro and must not be committed.

## Local Development

Install the lockfile-defined dependencies:

```sh
npm ci
```

Start the development server:

```sh
npm run dev
```

Check Astro and TypeScript diagnostics:

```sh
npm run check
```

Run the generated-site regression suite:

```sh
npm test
```

Create and inspect a production build:

```sh
npm run build
npm run preview
```

## Content

Update the Spanish and English structured content in `src/data/portfolio.ts` together. Keep technical claims public, specific, and verifiable; do not add corporate or home-network details. The existing GitHub client can support a future project archive, but the landing page prioritizes selected engineering evidence.

Add articles as Markdown or MDX files in `src/content/blog/`, with `title`, `description`, `locale`, and `pubDate` frontmatter; `tags`, `updatedDate`, and `draft` are optional. Published notes appear in the localized portfolio sections and at `/en/notes/<slug>/` or `/es/bitacora/<slug>/`. Draft entries are excluded from those routes and from `/rss.xml`.

## Signal Relay

The portfolio presents a public LXMF destination backed by a separate, self-hosted Reticulum bridge. It provides a contact address and bounded plain-text inbox; Prometheus scrapes operational metrics separately. Its public API, security boundary, container deployment, and acceptance checks are defined in [docs/SIGNAL-RELAY.md](docs/SIGNAL-RELAY.md) and [services/signal-relay/README.md](services/signal-relay/README.md). Do not add Reticulum identities, Telegram credentials, tunnel credentials, home IP addresses, or bridge configuration to this repository.

For local bridge setup, API/WebSocket tests, and end-to-end verification, use [services/signal-relay/README.md](services/signal-relay/README.md). GitHub Actions runs both the Astro suite and Signal Relay's Python suite before publishing the Pages artifact.

When refreshing Reticulum bootstrap transports or recovering a broken private configuration, follow the relay README's host procedure: preserve `.env`, the persistent relay data volume, and `lab-sender-reticulum/`; refresh the relay `compose.yaml` and merge the current Reticulum template, then recreate only `signal-relay`. Update the edge independently from [`destaben/lab-inverse-proxy`](https://github.com/destaben/lab-inverse-proxy). Update the private `SIGNAL_RELAY_PUBLIC_TCP_NODE_ALIASES` mapping whenever configured interface names change, and keep its public aliases aligned with `SIGNAL_RELAY_PUBLIC_TCP_NODE_URLS`.

## Deployment

Every push to `main` runs [.github/workflows/deploy-pages.yml](.github/workflows/deploy-pages.yml). The workflow uses Node 22, runs `npm ci`, builds `dist/`, and deploys the generated artifact to GitHub Pages. GitHub Actions is the only publishing path; do not commit generated files or publish from a branch.

In repository settings, set Pages **Source** to **GitHub Actions**. The published artifact includes `public/CNAME`; this preserves the domain in deployed files but does not configure the custom domain in GitHub by itself.

## Custom Domain

Set the Pages custom domain to `info.destaben.dev`, then create this DNS record at the authoritative DNS provider:

```text
info.destaben.dev CNAME destaben.github.io
```

Use DNS-only mode for this CNAME. Wait for GitHub to verify DNS and issue its certificate before enforcing HTTPS.
